# Лабораторная работа № 2 — уязвимости веб-приложений

**Тема:** демонстрация SQL Injection и Stored Cross-Site Scripting (XSS), а также исправление этих уязвимостей.

Проект предназначен только для локального обучения. Тестовые скрипты обращаются к приложению на `127.0.0.1`; не запускайте уязвимую версию в публичной сети и не направляйте скрипты на чужие сайты.

## 2. Подготовка окружения

Требуется Python 3.10 или новее.

### Windows (PowerShell)

Из каталога проекта выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Если PowerShell запрещает активацию окружения, можно запускать интерпретатор напрямую: `\.venv\Scripts\python.exe`.

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 3. Часть 1 — запуск уязвимого приложения

Из корня проекта:

```bash
python vulnerable_app/app.py
```

Приложение будет доступно только на этом компьютере: <http://127.0.0.1:5000>.

В приложении есть поиск публичных материалов и форма добавления комментариев. В базе автоматически создаётся демонстрационная закрытая запись с маркером `FLAG{SQL_INJECTION_DEMO_ONLY}`. Это вымышленная строка для проверки результата SQL-инъекции, а не настоящий секрет.

### Уязвимость № 1 — SQL Injection (CWE-89, OWASP A03: Injection)

В обработчике `/search` пользовательский параметр `q` напрямую вставляется в SQL-запрос с помощью f-строки. Из-за этого специальные символы и фрагменты SQL могут изменить условие выборки. Предполагается, что маршрут должен возвращать только строки с `is_private = 0`, но вредоносный ввод способен изменить логику `WHERE`.

### Уязвимость № 2 — Stored XSS (CWE-79, OWASP A03: Injection)

Комментарий сохраняется в SQLite, а затем выводится в шаблоне с фильтром Jinja `safe`. Фильтр отключает стандартное HTML-экранирование. Поэтому введённая HTML-разметка, включая JavaScript, может интерпретироваться браузером при открытии главной страницы.

## 4. Часть 2 — эксплуатация уязвимостей

Не останавливая сервер, откройте второе окно терминала в корне проекта.

### Проверка SQL Injection

```bash
python exploits/sql_injection.py
```

Скрипт отправляет запрос с тестовой строкой `' OR 1=1 -- ` и проверяет, появился ли в ответе маркер закрытой записи. Для уязвимой версии ожидается сообщение `[УСПЕХ]`.

### Проверка Stored XSS

```bash
python exploits/xss.py
```

Скрипт отправляет комментарий с демонстрационным JavaScript, затем загружает главную страницу и проверяет, вернулась ли строка без экранирования. Для визуальной демонстрации откройте <http://127.0.0.1:5000> в браузере: браузер обработает внедрённый script и покажет тестовое окно `alert`.

Скрипт не запускает JavaScript самостоятельно: он проверяет HTML-ответ, а выполнение демонстрируется в браузере.

## 5. Часть 3 — исправление уязвимостей

В исправленной версии используются два изменения.

1. **SQL Injection:** вместо конкатенации пользовательского ввода применяется параметризованный запрос `LIKE ?`, а значение передаётся отдельным аргументом в `db.execute`. Ввод рассматривается как данные, а не как часть SQL-кода.
2. **Stored XSS:** удалён фильтр `safe`. Jinja автоматически экранирует содержимое при выводе в HTML-контекст.

### Запуск исправленной версии

Остановите уязвимый сервер (`Ctrl+C`), затем запустите:

```bash
python patched_app/app.py
```

Исправленная версия доступна на <http://127.0.0.1:5001>.

В другом окне терминала выполните проверки:

```bash
python exploits/sql_injection.py --base-url http://127.0.0.1:5001
python exploits/xss.py --base-url http://127.0.0.1:5001
```

Ожидаемые результаты:

- SQL Injection: закрытая запись и маркер не возвращаются.
- Stored XSS: тестовый HTML возвращается экранированным как текст; JavaScript не должен выполняться в браузере.

### Diff-патч

Файл `patches/vulnerabilities.patch` показывает точечные изменения в `app.py` и `templates/index.html`. Это демонстрационный diff между уязвимой и исправленной логикой. Готовая исправленная версия также находится в каталоге `patched_app/`.

## 6. Вывод

В ходе лабораторной работы разработано локальное Flask-приложение с двумя намеренно внесёнными уязвимостями: SQL Injection и Stored XSS. С помощью Python-скриптов показано, как некорректная обработка пользовательских данных приводит к раскрытию закрытой записи и внедрению исполняемой HTML-разметки. Затем применены параметризованные SQL-запросы и контекстное HTML-экранирование, после чего повторные проверки должны подтвердить устранение уязвимостей.
